# Results

**Verdict in one line: the hypothesis `LLM < World Model < Unified` is not supported
as stated.** One leg is untestable in this environment, one leg holds only as an
ordering between two failing systems, and the third leg is contradicted.

The single most informative result is not about any architecture. It is that a
planner with *perfect* dynamics earns **+19.2%** per episode while every *learned*
system loses money and none beats doing nothing. The bottleneck in this world is
model accuracy, not the architecture of intelligence.

Generated by `configs/main.yaml` (config hash `aa8b3c823993`) over 620 episodes,
13 predictive systems and 13 control policies. Raw numbers:
`results/main/RESULTS.md`, `results/main/results.json`, `results/main/tables/`.

## 2. Control: nothing learned beats doing nothing

Mean total return per episode across five worlds, 4 episodes each (n = 20 paired
episodes per comparison).

| policy | return | Sharpe | max drawdown |
|---|---|---|---|
| **oracle_plan** (true simulator, privileged) | **+0.1916** | +0.144 | 0.068 |
| **noop** (do nothing) | **+0.0023** | +0.008 | 0.067 |
| buy_and_hold | −0.0076 | −0.007 | 0.082 |
| memory_only | −0.0404 | −0.044 | 0.111 |
| wm_greedy | −0.0422 | −0.069 | 0.116 |
| wm_plan | −0.0520 | −0.096 | 0.126 |
| wm_plan_memory | −0.0571 | −0.098 | 0.127 |
| random | −0.0584 | −0.052 | 0.120 |
| planner_no_model | −0.0750 | −0.076 | 0.184 |
| unified_no_memory | −0.0821 | −0.091 | 0.147 |
| unified | −0.1306 | −0.102 | 0.241 |
| unified_no_rollout | −0.1680 | −0.135 | 0.255 |
| llm (rule-based surrogate) | −0.2185 | −0.149 | 0.310 |

Read this table carefully, because the ordering is easy to over-read:

* The world-model planner **does** beat the reasoner by +0.167 return
  (p = 0.028). That is the `LLM < World Model` leg, and it is real. But **both
  lose money**, and `wm_plan` is also significantly *worse* than buy-and-hold
  (−0.045, p = 0.050). It is an ordering between two failing systems.
* Only the oracle planner beats do-nothing. Its margin over the learned planner
  is **+0.244 (p < 0.001)** — that gap is the headroom a better learned model
  could recover, and it is larger than every difference between the learned
  systems combined.
* Gas is real in this world, so trading has a cost floor. Doing nothing coming
  second is not an artifact; it is the correct benchmark, and it is the one
  every learned system failed to clear.

### Why the unified system underperformed

The gate collapsed. In the logged episode, `unified` took the `reason` pathway on
**99.4%** of decisions and planned on 0.6%; `unified_no_memory` did the opposite,
planning on 98.8%. Two variants of the same mechanism locked onto opposite arms,
which is the signature of premature convergence, not of learning.

LinUCB with ~160 decisions per episode and a reset at every episode boundary does
not have enough data to identify a three-armed contextual policy. Since the
`reason` pathway is the worst standalone system here, a gate that collapses onto
it inherits its losses — which is exactly the ordering observed
(`unified` ≈ between `llm` and `wm_plan`, closer to `llm`).

So `WM < Unified` fails, but the honest attribution is **the arbitration
mechanism, not the unified architecture**. A gate that cannot learn is not a test
of whether combining reasoning with simulation helps. This is a limitation of
this implementation, and it is the first thing to fix.

### 2.1 Is the unified system mis-wired? No - and its ceiling is the best result in the study

The natural suspicion when a combined system underperforms its parts is that a
capability has been crossed: the reasoner reading the wrong observation, the
planner holding a different model, the gate dispatching to the wrong arm. That is
testable rather than arguable.

**Wiring audit.** Pinning the gate to a single pathway must reproduce the
corresponding standalone system exactly. It does:

| forced pathway | actions identical to standalone? | return |
|---|---|---|
| always plan | **yes**, every step | −0.0224 vs `wm_plan` −0.0224 |
| always reason | **yes**, every step | −0.1195 vs `llm` −0.1195 |

No capability is crossed. The components are correctly connected, and the entire
deficit is *which* pathway the gate selects. This is now a regression test
(`test_unified_components_are_not_crossed`).

**The ceiling.** So how good could it be if arbitration worked? An *oracle gate*
forks the real simulator at every step, tries the action each pathway proposes,
and keeps whichever actually paid more. It is privileged — it sees the
consequence before committing — so it bounds what any gate could achieve with
these components (`scripts/gate_ceiling.py`, 6 episodes over two worlds):

| system | mean return |
|---|---|
| **unified, oracle gate** | **+0.1146** |
| `wm_plan` | −0.0202 |
| unified, learned gate | −0.1561 |
| `llm` | −0.3630 |
| *(reference)* do nothing | +0.0023 |
| *(reference)* oracle planner | +0.1916 |

With a working gate the unified system is **the only configuration built from
learned components that beats doing nothing**, and it closes roughly 60% of the
distance to a planner with perfect dynamics. The architecture has large headroom;
this implementation's gate throws all of it away and then some.

**Why arbitration is the whole game here.** The two pathways propose the *same*
action on only **0.8%** of steps. On the 99.2% where they disagree, the better
choice is the planner **44%** of the time and the reasoner **56%** — neither
dominates. That is the precondition for a gate to add value: if one pathway were
uniformly better, no arbitration could beat simply always using it. The signal
exists; LinUCB over three arms, reset every episode and fed ~160 decisions,
cannot find it.

**On efficiency, the intuition is half right.** Measured as episode wall time per
decision (which includes simulator cost, so treat the absolute values as an upper
bound on policy cost):

| system | ms per decision | imagined steps |
|---|---|---|
| `wm_plan` | 8445 | 8.3M |
| unified | 3255 | 8.3M |
| `llm` | 1365 | — |
| do nothing (env cost floor) | 1447 | — |

Net of the ~1.4s per-step simulator floor, the unified system spends roughly a
quarter of what always-planning does, because it only plans on the steps the gate
selects. So it *is* substantially cheaper than the world-model planner — it is
simply not more accurate, with this gate. A gate that is both selective and
correct would be cheaper **and** better; that combination is what §2.1's ceiling
measures and what item 1 of the follow-ups targets.

### 2.2 Trying to fix the gate: a null result, a real bug, and a correction

§2.1 measured an oracle-gate ceiling of +0.115 and I concluded the architecture
had large headroom that the gate was throwing away. Acting on that produced two
findings, one of which corrects §2.1.

**The fix did nothing.** The gate was fitted offline on 2560 decisions collected
on *training* seeds with a uniformly random arm (959 reason / 818 plan / 783
recall), then evaluated on the held-out control seeds:

| system | mean return |
|---|---|
| unified, warm-started gate | −0.1247 |
| unified, original gate | −0.1258 |
| `wm_plan` | −0.0520 |
| `llm` | −0.2185 |

`warmstart − baseline = +0.0011, p = 0.972`. A clean null. And the collapse it
was meant to cure *was* cured — pathway shares went from 99.4 / 0.6 / 0 to
36.9 / 30.1 / 33.0 — with no effect whatsoever on return. **Collapse was never
the cause.**

**Why: the context does not predict which pathway wins.** On 435 decisions where
the two pathways disagreed, with the oracle forking the simulator to see which
actually paid:

| quantity | value |
|---|---|
| oracle's better arm | plan 56.6% / reason 43.4% |
| fitted gate agrees with the oracle | **43.7%** |
| always guessing "plan" would agree | 56.6% |
| mean advantage of the right choice | $657 per decision |
| value the gate captured vs always-reason | **−$117 per decision** |

The gate is not merely uninformative, it is *anti*-correlated: it agrees with the
oracle less often than a constant guess, and destroys value relative to picking
one pathway and sticking to it. The stakes are large ($657 a decision), so the
headroom in §2.1 is real — but it is **not reachable from this context**. The
nine features (model-error EMA, volatility, solvency, basis, memory distance,
time) do not carry the signal.

**A real bug, in code older than this experiment.** `LinUCBGate.reset()`
recovered its ridge prior by reading `A[0][0, 0]`. That cell stops being the
ridge after the first update, because the context's bias term contributes 1.0 per
pull. The restored prior therefore compounded every episode — 1 → 54 → 107 → 160
— leaving the gate effectively frozen by the end of an evaluation and making
results depend on **evaluation order**. Confirmed directly: the same policy on
the same episode produces different actions on 58 of 80 steps depending on
whether it ran a prior episode first.

Consequences, stated plainly:

* The main run's `unified*` control figures were order-dependent and should be
  treated as approximate. `unified_baseline` re-measured in isolation is −0.1258
  against the main run's −0.1306; the conclusion is unaffected (both are far
  below `wm_plan`), but the exact numbers are not reproducible without fixing
  this. Every non-unified policy re-measured **byte-identically**, so nothing
  else in the study is touched.
* The bug is fixed (`ridge` is now stored explicitly) with two regression tests:
  reset is idempotent across episodes, and a gate with history selects
  identically to a fresh one after reset.

**Correcting §2.1.** I wrote there that "the architecture has large headroom;
this implementation's gate throws all of it away." The first half stands — the
oracle ceiling is real. The second half was wrong. The headroom is not
recoverable by better arbitration over this context; a correctly-fitted,
non-collapsed gate captures none of it. What §2.1 actually establishes is that
*outcome information* is worth +0.115 here, not that *arbitration* is.

**What would be worth trying next**, given this: the context is backward-looking
(an EMA of past model error) where the decision needs a forward-looking signal.
The obvious candidate is the planner's own predicted advantage for *this* state —
the score of its best imagined sequence against the score it assigns the
reasoner's proposed action — plus ensemble disagreement as an uncertainty
estimate. Both are available at decision time and neither is in the current
context.

and a linear autoregression:

| model | in-distribution | OOD mean | OOD worst |
|---|---|---|---|
| **gbdt** | **+0.214** | **+0.290** | **+0.003** |
| transformer | +0.158 | −0.011 | −0.595 |
| gnn | +0.145 | +0.059 | −0.486 |
| mlp | +0.104 | +0.019 | −0.480 |
| wm_transformer | +0.089 | −0.181 | −1.069 |
| linear | +0.031 | −0.363 | −2.585 |
| obsspace | +0.006 | −0.680 | −3.300 |
| wm_graph | −0.028 | −0.055 | −0.504 |
| wm_rssm_1step | −0.183 | +0.007 | −0.205 |

| wm_rssm | −0.616 | −0.103 | −0.567 |

Gradient-boosted trees win outright, and are the only system with a positive
worst-case OOD score. On this metric the world models lose to everything.

**But the pooled metric is dominated by the protocol group (48 features) over the
agent group (22).** Splitting them reverses the story:

| model | agent state (action-driven) | protocol state (market dynamics) |
|---|---|---|
| linear | **+0.535** | −0.010 |
| **wm_graph** | **+0.282** | −0.053 |
| **wm_rssm** | **+0.153** | −0.678 |
| wm_rssm_1step | +0.073 | −0.204 |
| transformer | +0.050 | **+0.167** |
| gnn | +0.022 | +0.155 |
| obsspace | +0.014 | +0.005 |
| mlp | +0.001 | +0.112 |
| wm_transformer | +0.001 | +0.096 |
| wm_jepa | +0.001 | −0.208 |
| gbdt | −0.002 | **+0.232** |

There is a clean dissociation. The latent world models learned the channel that
runs **from the agent's action to its own balance sheet** — the channel planning
actually needs — and failed at market dynamics. The discriminative baselines did
the reverse. `wm_rssm` is simultaneously the *worst* pooled predictor and the
second-best predictor of action consequences.

Averaging those two channels into one number makes both facts disappear. That is
why the per-group table is the finding and the pooled column is context.

### Leakage canary: clean

Price-level skill ranges from **−0.038 to 0.000** across all 13 systems. Price
changes are martingales by construction, nobody beat them, and no system is
reading the exogenous process. Contamination checks also pass: seeds disjoint
across all 10 splits, largest verbatim observation-row overlap with train
**0.00000**. The automated audit returned **no high- or medium-severity
findings**.

### Events are learnable; per-step reward is not

Every learned system predicts the ten discrete events well and is well
calibrated — `gnn` leads at AUROC **0.870**, ECE 0.006; world models trail at
0.78–0.86. Per-step reward, by contrast, is unpredictable: **every** system
scores negative skill against simply predicting the mean. Wealth changes in this
world are dominated by exogenous price moves, which is realistic and is why the
control task is hard.

## 4. Counterfactual reasoning: the simplest model wins

Skill against a zero-effect predictor ("the action changes nothing"), over 144
simulator-forked ground-truth pairs:

| model | mean cf skill | sign accuracy (material effects) |
|---|---|---|
| **linear** | **+0.517** | 0.636 |
| **wm_rssm** | **+0.144** | 0.599 |
| transformer | +0.010 | 0.587 |
| wm_rssm_1step | +0.001 | 0.604 |
| persistence / ar | 0.000 | — |
| obsspace | −0.031 | 0.541 |
| gnn | −0.034 | 0.583 |
| wm_jepa | −0.144 | 0.506 |
| mlp | −0.212 | 0.576 |
| wm_transformer | −0.265 | 0.611 |
| gbdt | −1.179 | 0.019 |
| wm_graph | −3.023 | 0.592 |

Three things matter here:

1. **A linear model with action features is by far the best counterfactual
   reasoner in this world**, positive on all eight settings. Single actions have
   small, near-additive effects, and a linear model estimates exactly that. This
   is a direct challenge to the idea that causal reasoning requires a learned
   latent world model.
2. **RSSM is the only latent model with real causal signal** (+0.144, positive on
   7 of 8 settings) and it beats its matched control `obsspace` (−0.031), which
   has the identical multi-step objective and no latent. So latent state *did*
   contribute something the objective alone did not.
3. `wm_graph` is bimodal: **+0.28 to +0.43** in-distribution and on novel
   mechanisms, but **−7.3 and −16.5** on unseen agents. It has genuine causal
   structure and no idea when that structure stops applying. Averaging to −3.02
   describes neither mode.

### 4.1 Does the multi-step objective buy the causal signal? (corrected ablation)

The main run trained `wm_rssm_1step` with 4.7x more KL than `wm_rssm`, so its
numbers conflated "shorter horizon" with "more regularisation". Both arms were
retrained under identical weighting (`configs/ablation_horizon.yaml`,
`results/ablation_horizon/`). Only the horizon differs.

| metric | L = 6 | L = 1 | difference |
|---|---|---|---|
| **counterfactual skill** | **+0.137** | **−0.009** | **+0.146** |
| decision-state, in-distribution | −0.616 | −0.255 | −0.360 |
| — agent group | +0.194 | +0.058 | +0.136 |
| — protocol group | −0.682 | −0.281 | −0.401 |
| decision-state, OOD mean | −0.102 | −0.013 | −0.089 |

**The open-loop objective trades one-step accuracy for causal understanding.**
Training to roll six steps forward costs 0.36 of one-step decision-state skill
and buys 0.146 of counterfactual skill. The one-step arm is the better one-step
predictor, which is exactly what it was optimised for; it has essentially no
causal signal (−0.009, i.e. no better than "the action changes nothing").

The trade lands unevenly across channels: multi-step training *helps* on the
agent's own balance sheet (+0.136) and *hurts* on protocol state (−0.401). The
horizon pushes the model to model its own action's consequences at the expense of
market dynamics — the same dissociation seen in §3, now shown to be caused by the
objective rather than merely correlated with architecture.

**A correction to an earlier reading.** When the corrected arms were trained,
their *validation losses* came out nearly identical (1.5388 vs 1.4962, against
0.7508 vs 1.4799 in the main run), and I took that to mean the apparent horizon
effect had been mostly a confound. That was wrong as a general statement. It held
for validation loss only. On the benchmark metrics the horizon effect is real and
almost unchanged by the correction — the counterfactual gap is +0.143 confounded
and +0.146 corrected. The confound inflated the *loss* gap, not the *capability*
gap, and validation loss was simply the wrong quantity to read it from.

### Why: action sensitivity predicts counterfactual skill

Representation diagnostics (`results/main/diagnostics.json`) explain the ordering
almost entirely. No model collapsed (latent std 0.29–0.77), but they differ
sharply in how much their predictions depend on the action:

| model | effective dim | relative action sensitivity | cf skill |
|---|---|---|---|
| wm_rssm | 3.6 / 224 | **0.830** | **+0.144** |
| wm_graph | 9.3 / 960 | 0.280 | +0.28 iid, −3.02 mean |
| wm_rssm_1step | 4.6 / 224 | 0.238 | +0.001 |
| obsspace | 28.4 / 112 | 0.189 | −0.031 |
| wm_jepa | 24.1 / 128 | 0.134 | −0.144 |
| wm_transformer | 9.3 / 128 | 0.055 | −0.265 |

Action sensitivity ranks the models in almost exactly counterfactual order. A
model whose predictions barely move when the action changes **cannot** reason
counterfactually — not as a matter of training, but by construction.

This also explains RSSM's split personality: an effective dimensionality of
**3.6 out of 224** is posterior collapse in all but name. Its KL term crushed the
latent down to a few action-driven directions, which is why it tracks its own
balance sheet well, predicts market state terribly, and still reasons causally.
JEPA shows the mirror image — a rich 24-dimensional latent that largely ignores
actions, giving good representation and no causal signal.

## 7. Limitations

Stated plainly, because several of them bound what the results can mean.

1. **The LLM leg is untested.** No API credentials were available, so System 1
   ran as the rule-based reasoner and every row is labelled
   `rule_based_offline`. The `LLM < World Model` result is really
   `rule-based reasoner < world model`. A real language model might do better or
   worse; this experiment does not say. The Anthropic/OpenAI client is
   implemented, cached and tested — it needs only a key.
2. **The unified result measures a broken gate, not a broken architecture.**
   See §2. LinUCB over three arms cannot be identified from ~160 within-episode
   decisions.
3. **The horizon ablation was confounded in the main run and has been rerun.**
   The main run's `wm_rssm_1step` carried 4.7x more KL than `wm_rssm`. Both arms
   were retrained under equal weighting; see §4.1. The conclusion survived, and
   the main-run figures for that arm should be read from §4.1 instead.
4. **`wm_graph` had ~3x fewer parameters** (297k vs 463k–902k) because its
   training cost forced a smaller configuration. Where it underperforms, capacity
   is a live alternative explanation.
5. **n = 4 episodes per world.** Pooled across five worlds this gives n = 20
   paired comparisons, enough for the head-to-head tests reported. Per-scenario
   claims are not significant at this size — the smallest attainable two-sided
   p-value at n = 4 is 0.125.
6. **Gate-usage figures come from the last logged episode**, not aggregated
   across all episodes.
7. **One world, one focal agent.** Every number is specific to this simulated
   economy. The linear model's counterfactual dominance in particular may be a
   property of small, near-additive single-action effects and need not transfer
   to environments with strong action interactions.
8. **Sign accuracy is undefined for zero-effect predictors.** `gbdt` scores
   0.019 because it predicts near-zero effects and `sign(0)` matches nothing;
   read its cf skill, not its sign accuracy.

## 8. Conclusion

**Does the evidence support `LLM < World Model < Unified`?** No.

* `LLM < World Model` — **holds as an ordering** in control (+0.167, p = 0.028),
  but between two systems that both lose money, and with the LLM replaced by a
  surrogate. Weak support at best.
* `World Model < Unified` — **contradicted as built** (−0.079), but the cause is
  isolated and the idea is vindicated. The components are provably not
  mis-wired (§2.1), the two pathways disagree on 99.2% of steps with neither
  dominating, and with a perfect gate the unified system scores **+0.115** —
  better than every other learned system and the only one to beat doing nothing.
  This refutes *this gate*, and is evidence **for** unification.

**Does a learned world model provide capabilities better function approximation
does not?** Partially, and not where expected.

The evidence *for*: RSSM is the only latent model with genuine causal signal, it
beats its exactly-matched no-latent control, and latent models dominate the
action-conditioned prediction channel that discriminative baselines fail at.
Action sensitivity — an architectural property, not a training outcome —
predicts counterfactual skill almost perfectly.

The evidence *against*: a linear model with action features is the best
counterfactual reasoner by 3.6x. Gradient-boosted trees win pooled prediction and
generalise best out of distribution. Planning through the learned model does not
beat one-step greedy use of the same model. And no learned system, world model or
otherwise, beats doing nothing.

The most defensible reading is that **this experiment did not test the hypothesis
under favourable conditions**. The +0.244 gap between perfect and learned
dynamics says the environment rewards accurate world models richly; the learned
models simply were not accurate enough for planning through them to pay. RSSM's
effective dimensionality of 3.6 out of 224 says why — the models are underfit and
over-regularised, not conceptually inadequate.

That is a statement about this lab's models, and it is the honest one. It would
be easy to report "world models beat the LLM baseline, hypothesis supported" from
the same data. That claim would be true in isolation and misleading in context,
which is the failure mode the whole design — the zero-effect control, the
leakage canary, the matched objective control, the pre-registered checks — exists
to prevent.

### What to do next, in priority order

1. Give the gate enough data to learn (persist across episodes, or replace
   LinUCB with a simple learned critic) and re-test `WM < Unified`.
2. Fix RSSM's posterior collapse — lower `kl_weight`, raise `free_nats`, or use
   a categorical latent — and re-check whether protocol-state prediction recovers.
3. Run with real LLM credentials to test the leg that is currently untestable.
4. Train longer. 2250 gradient steps is a small budget, and the +0.244 oracle gap
   is the prize for closing it.
5. Reduce `kl_weight`. The corrected ablation charges the regulariser at its
   configured value, which is 4.7x the main run's effective strength, and RSSM
   was already collapsed at the weaker setting. Both this and item 2 point the
   same way.
